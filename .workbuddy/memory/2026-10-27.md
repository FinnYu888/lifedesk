## 修复：收藏卡片编辑时环境/版本/截图字段丢失
- 现象：卡片上填写的环境、CDS 版本、图片 URL 都没保存；本地图片也不显示。
- 排查：新建（POST insert 整个实体）字段能存（id=43 有 env/cdsVersion）；编辑被丢。local-file 接口正常（200/image/jpeg）。
- 根因 ①：`FavoriteService.update()` 只回写 name/value/type/description，env/cdsVersion/screenshot 被忽略。
- 根因 ②（潜伏）：MyBatis-Plus updateById 默认 NOT_NULL 字段策略，set null 清空不生效（description 同病）。
- 修复（commit 55345f3，远程 main = 65087b61da，已合入本地 main）：
  - update() 补齐三字段回写，null/空串写 null 表示清空
  - Favorite 实体 env/cdsVersion/screenshot/description 加 @TableField(updateStrategy = FieldStrategy.IGNORED)
- 验证：PUT 三字段 → 回读一致；PUT null → 清空生效；vite proxy local-file 200/56558B。
- 经验：MP updateById 不写 null 字段，需要"可清空"的字段必须配 FieldStrategy.IGNORED；排查"字段没保存"先分清新 vs 编辑两条链路。

## 应用点击不弹窗修复（远端 a2699e9）
- 症状：常用App 点击 Postman「没启动」——实际进程在跑但 MainWindowHandle=0 永无窗口（单进程 34MB 卡住）
- 根因：WorkBuddy 宿主是 Electron，工具链环境带 ELECTRON_RUN_AS_NODE=1，ProcessBuilder 原样传给目标应用，Electron 系应用（Postman/VSCode/Cursor）因此以无界面 Node 模式启动
- 修复：launch 时 pb.environment().remove 掉 ELECTRON_RUN_AS_NODE / NO_ATTACH_CONSOLE / ENABLE_LOGGING / ENABLE_STACK_DUMPING
- 运维注意：后端需用 PowerShell 工具 run_in_background 启动（Bash 工具链即使非沙箱也有窗口问题）；验证窗口看 MainWindowHandle 是否非 0，34MB 单进程=典型 run-as-node 卡死态
