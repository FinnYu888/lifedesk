## 自定义菜单功能（iframe 嵌入外部网站）
- 需求：在 LifeDesk 侧栏支持自定义菜单；点击"+"新增按钮（与上方 nav-item 同宽同高）弹窗填名称+URL，新增菜单后点击即在当前系统内通过 iframe 嵌入展示该网站，不跳转新窗口。先用 http://10.139.92.114:8098/#/login（RPT 接口测试用例平台）验证。
- 实现（commit eef2589，已推送 origin workbuddy/main-68c2317f）：
  - 后端：新增 `com.lifedesk.custommenu` 模块（entity/mapper/service/controller），REST `/api/custom-menu`，仿 favorite 模式。
  - DB：schema.sql 新增 `custom_menu` 表；data.sql 预置 RPT 接口测试用例平台菜单。
  - 前端：
    - `src/api/customMenu.ts` API
    - `src/composables/useCustomMenus.ts` 模块级单例 composable（MainLayout 与视图共享 customMenus 状态）
    - `src/views/custommenu/index.vue` iframe 嵌入视图（带 loading 占位 + 编辑/删除/新窗口打开）
    - `MainLayout.vue` 侧栏新增"自定义"分组 + 末尾"+"新增按钮（与 nav-item 同宽同高，虚线描边区分）+ 新增弹窗
    - `router/index.ts` 注册 `/custom` 子路由
  - 构建验证：vite build 通过（2277 模块，30.63s）。
- 推送要点：本地代理 127.0.0.1:60616 对 github.com 持续返回 502 CONNECT tunnel；改用 `HTTPS_PROXY= HTTP_PROXY= git push` 直连成功（origin 之前无 workbuddy/main-68c2317f 分支，作为新分支推送）。
- 技术决策：
  - 自定义菜单数据走后端持久化（而非 localStorage），便于多设备/重启保留。
  - iframe 用 sandbox=allow-scripts allow-same-origin allow-forms allow-popups ... 兼顾安全与嵌入站可用性（登录/表单/弹窗）。
  - 路由用 query 携带 id/name/url 而非动态路由注册，避免每次增删菜单要动态加路由。
  - composable 不在内部调 useRouter().push（await 后丢当前实例），导航由调用方在自己 setup 上下文里 router.push。

## 运行时修复：前后端未加载新代码
- 现象：用户反馈侧栏看不到"+ 新增菜单"按钮，也看不到预置 RPT 菜单。
- 根因：代码已写好并推送，但运行中的前端 dev server（PID 38984）和后端 Spring Boot（PID 49784）都是改代码**之前**启动的旧版本；curl `http://localhost:8080/api/custom-menu` 返回 404 证实后端是旧版本。
- 修复：用 PowerShell `Stop-Process -Id 38984,49784 -Force` 停掉旧进程（Git Bash 的 taskkill /F 会被 MSYS 路径转换破坏，改用 PowerShell）；后台重启 `mvn spring-boot:run`（后端，约 2 分钟编译+启动）和 `npm run dev`（前端）。
- 验证：curl `/api/custom-menu` 返回 200 + RPT 菜单数据；前端 dev server 监听 8081。
- 教训：改完代码后需提示用户重启 dev server / 后端，或主动重启；HMR 对大改动不可靠。
